# Patch 13.2 — Compatibilidad Dashboard Experience V2 con Patch 13

**Base exacta:** `2dd2ae90909b55babe2467469c4fc2765cbeae8b` (V2 integrada en `main`).  
**Rama de preparación:** `fix/patch-13-2-dashboard-v2-payments`.

## Objetivo

Sin modificar la identidad visual, los estilos ni la estructura de Dashboard V2,
sincronizar la pantalla de pedido pendiente y la administración de medios de pago
con las reglas del backend incorporadas en el Patch 13.

## Cambios

- El detalle de pedido ya **no ofrece tres opciones fijas**. Consulta
  `GET /api/v1/payments/methods/?currency=<moneda de la orden>`.
- Se conservan los iconos, tarjetas, radios, botones y navegación visual V2;
  el backend define id, texto y disponibilidad.
- Si el listado está cargando, falla o está vacío, se informa sin crear pagos.
- Si se cambia o desactiva un método, la selección anterior no se reutiliza.
  `POST /payments/create/` recibe la moneda de la orden y el proveedor válido.
- MercadoPago Chile/Argentina y PayPal usan el enlace devuelto por la API;
  transferencias, Payoneer y Global66 abren las instrucciones de la orden.
  No se navega a URLs vacías o ajenas a HTTPS.
- Se corrige el formato del importe del pedido en CLP, ARS y USD, además de
  la etiqueta que decía «Total Pagado» en pedidos todavía pendientes.
- Se corrige la firma de `refetchInterval` de React Query v5 y la invalidación
  de caché tras cancelar un pedido.
- Administración: se incluye Global66 (CLP) en el selector; dLocal queda
  rotulado como «próximamente» e inhabilitado para nuevas altas/activación.
  Se aclara que un método configurado puede no ser visible si le faltan
  cuentas/alias o no admite la moneda. No se simula su disponibilidad.
- Tras editar cuentas o métodos, se invalida la caché de disponibilidad.

## Alcance

Solo frontend, pruebas unitarias y documentación. **No se cambian**
`backend/`, modelos, migraciones, backend de cobros, `cloudbuild.yaml`,
estilos, tokens de marca, layouts V2 ni dependencias. No ejecuta pasarelas.

## Pruebas

Desde `frontend` (Node/npm; no se requiere Python):

```bash
npm ci
npm run test:unit
npm run build
```

Se añade `dashboard-payment-methods.test.mjs` a `test:unit` para validar
cinco casos: API vacía, selección obsoleta, filtrado de proveedor no implementado,
redirects HTTPS y rutas de transferencias.

Validación funcional antes de desplegar:
- Pedido pendiente CLP, USD, ARS: los métodos coinciden con la API.
- Cuenta activa/inactiva y alias Global66: la opción aparece o desaparece.
- Tras activar/desactivar una cuenta, no deben quedar opciones engañosas.
- Pedido sin métodos: CTA de pago deshabilitado; cancelar pedido permanece habilitado.
- Pago por transferencia: instrucciones correctas, sin duplicar intentos manualmente.
- Retorno Mercado Pago/PayPal y cancelación: comprobar resultado autenticado.
- Dashboard admin/usuario V2: comparar con diseños aprobados.

**No marcar funcionalidad de cobro como certificada sin pruebas con sandbox.**
Los flujos de idempotencia, expiración y reconciliación corresponden al Patch 14.
